      Conceptos

      ¿Qué es un interbloqueo?

      Un interbloqueo (deadlock) ocurre cuando un grupo de procesos queda esperando para siempre porque cada uno retiene algo que otro necesita.

      🔪 🪵

      Un ejemplo cotidiano

      Ana toma el cuchillo y necesita la tabla; Beto toma la tabla y necesita el cuchillo. Ambos esperan para siempre.

      Reto de experimentación

      Con bloqueo vs. sin bloqueo

      Mismos procesos, mismos recursos. Lo único que cambia es el orden en que se piden.

      CON BLOQUEO

      Orden opuesto

      P1 pide R1 → R2 y P2 pide R2 → R1. Cada uno agarra uno y espera el otro: interbloqueo.

      Probar ▶
      SIN BLOQUEO

      Orden global (R1 antes que R2)

      Ambos piden R1 → R2. P2 espera, pero sin retener nada, así que el ciclo nunca se cierra.

      Probar ▶

      Conclusión: imponer un orden global rompe la espera circular. Esperar no es lo mismo que estar interbloqueado.

      01

      Grafo de asignación

      El simulador dibuja el sistema como un grafo que se actualiza después de cada acción:

      • Los círculos son procesos (P1, P2…).
      • Los cuadros son recursos; cada punto es una instancia (● asignada, ○ libre).
      • Una flecha continua R → P indica que el recurso está asignado al proceso.
      • Una flecha punteada P → R indica que el proceso está esperando el recurso.
      Ir al simulador →
      02

      Solicitar y liberar

      • Al solicitar, si hay una instancia libre se asigna de inmediato; si no, el proceso se bloquea y entra a una fila (FIFO).
      • Al liberar, la instancia pasa automáticamente al primero de la fila.
      • Al finalizar un proceso, se libera todo lo que tenía.

      Cada acción queda escrita en el registro de eventos.

      Ir al simulador →
      03

      Detección de ciclos

      Después de cada acción el simulador busca ciclos en el grafo y los explica con palabras, por ejemplo:

      P1 → R2 → P2 → R1 → P1

      Luego ejecuta el algoritmo de detección para confirmar si el ciclo es un interbloqueo real (rojo) o solo una espera circular posible (amarillo).

      04

      Recuperación

      Cuando hay interbloqueo, el panel de análisis ofrece:

      • Abortar un proceso: libera todo y los demás pueden seguir.
      • Expropiar un recurso: quitárselo a un proceso y dárselo al que espera.
      • Recuperación automática: aborta víctimas hasta que desaparece el bloqueo.

      El simulador sugiere la víctima que deja menos procesos bloqueados y pierde menos recursos.

      Cómo usar el simulador

      1. La forma más rápida: en 3 · Escenarios elige uno y pulsa Paso ▶ o Ejecutar todo ⏩.
      2. A mano: crea procesos y recursos en 1 · Crear nodos.
      3. Elige un proceso y un recurso en 2 · Operar y pulsa Solicitar, Liberar o Finalizar.
      4. Mira el aviso superior: verde = sin bloqueo, amarillo = ciclo sin interbloqueo, rojo = interbloqueo.
      5. A la derecha, Análisis del sistema explica el ciclo y ofrece opciones de recuperación.

      Procesos, recursos e instancias

      Proceso
      Un programa que se está ejecutando (Chrome, Word, Spotify…). En el simulador: un círculo.
      Recurso
      Algo que un proceso necesita para trabajar: impresora, archivo, cámara, memoria. En el simulador: un cuadro.
      Instancia
      Cuántas copias iguales hay del recurso (2 impresoras = 2 instancias). En el simulador: los puntos dentro del cuadro.

      En el ejemplo, Ana y Beto son procesos y el cuchillo y la tabla son recursos. Esperar es normal; el problema es cuando la espera nunca termina.

      Condición 1

      Exclusión mutua

      Un recurso no se puede compartir: mientras un proceso lo usa, los demás deben esperar.

      Ejemplo

      Una impresora imprime un documento a la vez.

      En el simulador

      Cada punto ● de un recurso pertenece a un solo proceso.

      Cómo romperla

      Hacer el recurso compartible (p. ej. archivos de solo lectura). No siempre es posible.

      Condición 2

      Retención y espera

      Un proceso conserva los recursos que ya tiene mientras espera otros.

      Ejemplo

      P1 tiene R1 y pide R2 sin soltar R1.

      En el simulador

      Un proceso con una flecha continua que llega (tiene algo) y una punteada que sale (espera).

      Cómo romperla

      Pedir todos los recursos al inicio, o soltar todo antes de pedir más.

      Condición 3

      No expropiación

      Nadie puede quitarle un recurso a un proceso; solo él decide cuándo soltarlo.

      Ejemplo

      El sistema no puede quitar la impresora a mitad de una impresión.

      En el simulador

      Los recursos solo se liberan con Liberar… salvo que uses la recuperación.

      Cómo romperla

      Permitir que el sistema quite recursos. Eso es justo lo que hace la opción de recuperación Expropiar.

      Condición 4

      Espera circular

      Existe una cadena cerrada de procesos, donde cada uno espera un recurso que tiene el siguiente.

      P1 → R2 → P2 → R1 → P1
      En el simulador

      Las flechas del ciclo se pintan de rojo.

      Cómo romperla

      Pedir los recursos siempre en el mismo orden global (ver el escenario Orden global).

      Paso 1

      Construye el grafo

      Cada asignación es una flecha R → P y cada espera es una flecha P → R.

      Las matrices de Asignación y Solicitud del simulador muestran la misma información en forma de tabla.

      Paso 2

      Busca ciclos

      Simplifica el grafo a un grafo de espera: P → Q si P espera algo que tiene Q.

      Luego lo recorre con una búsqueda en profundidad (DFS). Si un camino regresa al proceso inicial, hay un ciclo: una espera circular.

      Paso 3

      Confirma el bloqueo

      Algoritmo de detección: simula qué procesos podrían terminar con lo que hay libre.

      Work ← Disponible ; Finish[i] ← false
repetir
  buscar Pi: Finish[i] = false y Solicitud_i ≤ Work
  Work ← Work + Asignación_i ; Finish[i] ← true
Los Pi con Finish = false están interbloqueados

      El simulador muestra esta traza paso a paso en Algoritmo de detección.

      Importante

      ¿Un ciclo siempre es interbloqueo?

      1 instancia por recurso

      Sí: ciclo = interbloqueo.

      Varias instancias

      No necesariamente: otro proceso fuera del ciclo puede soltar una copia y romperlo.

      Probar el escenario “Ciclo sin interbloqueo” ▶
      CON BLOQUEO

      Orden opuesto

      1. P1 solicita R1 ✔
      2. P2 solicita R2 ✔
      3. P1 solicita R2 ⏳ (lo tiene P2)
      4. P2 solicita R1 ⏳ (lo tiene P1)

      Resultado: se forma el ciclo P1 → R2 → P2 → R1 → P1. Cada uno retiene lo que el otro necesita: interbloqueo.

      Probar en el simulador ▶
      SIN BLOQUEO

      Orden global (R1 antes que R2)

      1. P1 solicita R1 ✔
      2. P2 solicita R1 ⏳ (espera sin retener nada)
      3. P1 solicita R2 ✔, trabaja y libera todo
      4. P2 recibe R1, luego R2 ✔ y termina

      Resultado: P2 espera, pero no retiene nada mientras espera, así que nunca se cierra un ciclo. Todos terminan.

      Probar en el simulador ▶

      Comparación completa

      CriterioCon bloqueoSin bloqueo
      Orden de peticiónP1: R1→R2 · P2: R2→R1Ambos: R1→R2
      Retención y esperaSí, ambosNo: P2 espera con las manos vacías
      Espera circularSíNo
      Estado finalInterbloqueoTodos terminan

      Conclusión: imponer un orden global a los recursos rompe la condición de espera circular. Esperar no es lo mismo que estar interbloqueado.

        Limitaciones conocidas

        • Cada solicitud pide una instancia y un proceso bloqueado espera un solo recurso a la vez.
        • La simulación es por eventos: no hay hilos reales, tiempos de CPU ni planificador.
        • Se implementan detección y recuperación; no prevención ni evitación (algoritmo del banquero).
        • La expropiación libera el recurso pero no simula el rollback del proceso.
        • La víctima se elige con una heurística (bloqueados restantes e instancias perdidas), sin prioridades.
        • Pensado para grafos didácticos: máximo 9 instancias por recurso y 100 ciclos reportados.
